# Decisions

- 2026-08-12 — Pin pnpm 11 and require Node 22+ because the Cloudflare and TanStack toolchain support that boring LTS baseline.
- 2026-08-12 — Treat every root Markdown AST node except frontmatter as a block; this gives comments and diffs stable anchors for prose as well as components.
- 2026-08-12 — Normalize block source by converting CRLF to LF and trimming outer whitespace; author formatting inside a block remains significant.

- 2026-08-12 — Report single-line block children as `block-children-lines`, keeping the finding distinct from vocabulary errors so authors can fix formatting directly.
- 2026-08-12 — Use compatibility date 2026-08-04 because pinned workerd 2026.8.4 rejects 2026-08-12 as a future date.
- 2026-08-12 — Use one production D1 database and one KV namespace with the same binding names locally and remotely so Worker code has no environment-specific branches.
- 2026-08-12 — Execute plan, version, block, and decision writes as one raw D1 batch so atomicity is explicit and every block insert stays below the 100-parameter limit.
- 2026-08-12 — Replace author frontmatter in negotiated Markdown with canonical product metadata while preserving the byte-exact source on the JSON API for CLI pulls.
- 2026-08-12 — Commit a deterministic local seed identity, linked fake Clerk Organization, and token so integration and smoke runs do not depend on hosted authentication.
- 2026-08-12 — Store the service base URL beside the CLI token instead of hardcoding a production origin; environment variables override both values.
- 2026-08-12 — Resolve plan URLs through authenticated list and detail APIs so `pull` returns the stored source byte-for-byte rather than transport frontmatter.
- 2026-08-12 — Key `.plantifiles.json` by git-root-relative file path, falling back to the working directory only outside a repository.
- 2026-08-12 — Adopt a light playful green identity (`--primary: oklch(0.841 0.238 128.85)` over warm hue-107 neutrals) and re-derive the plan-block tokens against it, keeping judgment cool (`--decision` at hue 245) and risk red, because a green product still needs a red high risk.
- 2026-08-12 — Compile MDX to serializable HAST in the route loader so SSR and hydration share one strict registry without shipping the Node-only normalizer to browsers.
- 2026-08-12 — Export the structural diff as a browser-safe core subpath because the core barrel also exports the `node:crypto`-based normalizer.
- 2026-08-12 — Convert CSS token colors through a one-pixel canvas before passing them to Mermaid because Mermaid rejects the design system's OKLCH values.
- 2026-08-12 — Promote an in-review plan automatically once its last open decision is resolved and its current version has one approval.
- 2026-08-12 — Use the stable MCP TypeScript SDK v2 split server package and require both token and service URL so the stdio adapter stays a thin HTTP client.
- 2026-08-12 - Keep one canonical write-plan skill at `skills/write-plan/SKILL.md` and bundle that exact source into the Worker download route rather than maintaining a public-file copy.
- 2026-08-12 - Render persisted timestamps in an explicit UTC format so Worker SSR and browser hydration produce identical text in every locale.
- 2026-08-12 — Translate thrown `Response` objects into `notFound()`/`redirect()` at the loader boundary via `guardLoader`, because a raw `Response` reaching the router's dehydration step fails seroval and returns 500 instead of the intended status.
- 2026-08-12 — Map 403 to the 404 page rather than a distinct "forbidden" screen so a plan the viewer cannot see does not confirm its own existence.
- 2026-08-12 — Resolve the theme in a blocking inline script in `<head>` rather than in the provider effect, since the server cannot know the preference and hydration-time switching paints light first.
- 2026-08-12 — Register both Shiki themes with `defaultColor: false` so code blocks follow the `.dark` class through CSS variables instead of pinning `github-dark` in both modes.
- 2026-08-12 — Keep `--accent` as the neutral interaction surface shadcn expects and carry identity with `--primary` for fills plus a new `--brand-ink` (`--chart-3`/`--chart-2`) for text and strokes, because the bright chartreuse primary fails contrast as body-sized ink.
- 2026-08-12 — Drive diagram colours from the chart ramp (`--diagram-node`/`--diagram-edge`) and hand Mermaid the whole palette rather than four variables, because its `base` theme derives what it is not given by rotating the primary hue, which turned a green product's edge labels magenta.
- 2026-08-12 — Give the product three typographic voices — Inter for chrome, Newsreader for document display type, JetBrains Mono for editorial furniture — so a plan reads as a reviewed manuscript instead of a settings page.
- 2026-08-12 — Declare reading measures as `--container-*` tokens (`measure` 68ch, `gutter`, `rail`) so no route hardcodes a column width and the prose measure survives layout changes.
- 2026-08-12 — Replace the labelled 15rem nav sidebar with a 3.5rem icon spine plus Radix tooltips, spending the reclaimed width on the document's left margin instead of naming three destinations in chrome.
- 2026-08-12 — Number diagrams once from the normalized block list and pass the map through the render context, so the caption, the margin mark, and the lightbox title always cite the same figure.
- 2026-08-12 — Group the dashboard by what a reader must do — unresolved decisions first, then review state — rather than presenting eight equal-weight columns, because the index exists to route attention.
- 2026-08-12 — Warn rather than error when a plan carries fewer than two diagrams, so existing single-diagram plans stay publishable while the lint score nudges authors toward varied diagram types.
- 2026-08-12 — Parse with `remark-gfm` in `packages/core` as well as the renderer. Without it the two disagreed about Markdown: a comparison table collapsed into one paragraph and tripped `paragraph-length`, blocking the publish with a diagnostic that blamed paragraph length, and `- [ ]` checklists inside `<Phase>` — which the authoring skill instructs every agent to write — parsed as unchecked-null items with literal brackets left in the text.
- 2026-08-12 — Correction to the earlier claim that editor lint and publish shared one gate: they did not, for tables and checklists, because only the renderer had `remark-gfm`. The parity fix above is what makes that claim true.
- 2026-08-12 — Adding gfm rekeys blocks, because `normalize` derives kind from node type and ordinals are per-kind, so a table flipping `Paragraph` to `Table` shifts later paragraph ordinals in the same section. Measured the exposure before shipping: one published version contained a pipe table and it carried no comments, so no anchors moved and no migration was needed.
- 2026-08-12 — Drizzle's generated SQLite `plan` rebuild enabled foreign keys before dropping the old table, which cascaded into every plan-owned row. The migration now snapshots and restores versions, blocks, comments, decisions, and approvals around the rebuild; a copy of the 34-version local database preserved all row counts.
- 2026-08-12 — Resolve plan emoji as request API field, then current-version frontmatter, then the stored plan value on version updates; the explicit API field wins when both request and frontmatter are present, while omission does not erase an existing visual identity.
- 2026-08-12 — Drop status group headers from the plans index so one continuous grid can hold three useful cards across the deliberately narrow shell; the existing status filter remains the explicit grouping control.
- 2026-08-12 — Backfill existing plans in the emoji migration by subject (`🧾` billing, `🧭` drift, `🤝` ownership, `✅` approvals, `🔌` MCP, `🧪` table probes, `📝` fallback) so the card grid launches without empty anchors.
- 2026-08-12 — Keep workspace identity and review policy in one form spanning two named sections, with a single owner-only action footer, so save scope stays explicit without returning to one undifferentiated settings card.
- 2026-08-12 — Let the shared settings row accept rich labels so member avatars, names, and email addresses use the same row contract as scalar controls instead of creating a second member-only layout primitive.
- 2026-08-12 — Port individual primitives from `recalio/packages/ui` rather than adopting the package wholesale. Its component set is larger but carries `@tabler/icons-react` alongside Lucide, `@uiw/react-md-editor`, embla-carousel, react-hook-form, and both the unified `radix-ui` package and individual `@radix-ui/*` packages. Copying `card`, `input-group`, `label`, and `skeleton` gives the shared vocabulary without ~10 unused dependencies in a Worker bundle.
- 2026-08-12 — Map `--font-heading` to `--font-sans` so ported recalio components style correctly instead of silently no-opping on an undefined utility.
- 2026-08-13 — Add a top-level `<Prototype>` plan block containing one fenced HTML document and compile its static class attributes with Tailwind v4 at read time, keeping realistic product iteration inside the same immutable, diffable, commentable plan model instead of creating a separate artifact type.
- 2026-08-13 — Render prototype HTML only in an opaque-origin sandboxed iframe after removing executable tags, event handlers, embedded documents, form destinations, and unsafe URLs; generated documents deny scripts, connections, forms, and child frames through CSP while allowing inline styles plus HTTPS/data media.
- 2026-08-15 — Carry the green identity through the neutrals, not just the accent: light surfaces cast the identity hue at low chroma (hue 130) and the dark theme replaces the shadcn warm-stone ramp with hue-138 tinted surfaces, because a warm-grey chrome read as an amber product with a green button bolted on.
- 2026-08-15 — Give `--primary` dark green ink (`--primary-foreground: oklch(0.24-0.26 …)`) in every theme that uses the bright chartreuse fill, since near-white on an L≈0.72 lime failed contrast on buttons and chips.
- 2026-08-15 — Rename the default theme `cream` to `sprout` (`.theme-sprout`) once its paper turned green, so the picker label still describes what it paints; stored `cream` preferences fall back to the default.
- 2026-08-21 — Stop accepting new `<Prototype>` blocks and render immutable historical ones as inert source, removing iframe hosting, HTML sanitization, runtime Tailwind compilation, and their security surface.
- 2026-08-21 — Keep one Sprout palette plus dark mode and one fixed 68ch reading measure; theme galleries, downloadable reader fonts, and typography steppers added preferences without strengthening plan review.
- 2026-08-21 — Use compact dashboard rows instead of elevated cards so title, status, decisions, and version remain scannable without decorative height or motion.
- 2026-08-22 — Adopt the regenerated radix-luma idiom everywhere instead of only in `packages/ui`: containers carry a ring rather than a 1px border, and the radius ladder is fixed at `rounded-4xl` for page-level bars and dialogs, `rounded-3xl` for cards and fields, `rounded-2xl` for anything nested, `rounded-xl` for inline marks. Two utilities, `surface-card` and `surface-inset`, hold the composite so no route re-spells it.
- 2026-08-22 — Replace full-bleed `divide-y border-y` lists with discrete rounded rows separated by space and a hover surface. Compact rows survive from 2026-08-21; the hairlines do not, because a rule between two 1.375rem-radius surfaces reads as a seam.
- 2026-08-22 — Declare `--brand-ink`, `--decision` and `--diagram-node` outright rather than aliasing `--chart-*`. The olive base color turned the chart ramp neutral, so `--brand-ink: var(--primary)` painted body-sized ink in L≈0.84 chartreuse and `--decision`/`--diagram-node` lost their hue entirely. `--diagram-edge` also stops aliasing `--border`, which is now alpha white and cannot survive Mermaid's canvas conversion.
- 2026-08-22 — Keep the Mermaid node fill dark in both themes. Its base theme paints actor labels light on both sides, so a fill that tracks `--brand-ink` (light green in dark mode) puts white text on lime.
- 2026-08-22 — Mount `TooltipProvider` once in the root document. The regenerated tooltip no longer self-provides, and without it every plan page with a comment affordance threw during `renderToReadableStream`.
- 2026-08-22 — Size dialog overrides with the same breakpoint the primitive uses (`sm:max-w-*`). `DialogContent` now caps itself at `sm:max-w-md`, which no unprefixed `max-w-*` override can beat above mobile; the diagram lightbox was clipped until the override carried `sm:`.
- 2026-08-22 — Own the CSS dependencies where the CSS lives: `shadcn/tailwind.css` (the source of the `data-open`/`data-checked` variants the primitives rely on) and the font packages belong to `apps/web`, not `packages/ui`, which imports no CSS at all. They previously resolved only through pnpm's hidden hoist directory.
- 2026-08-22 — Run local dev as the `dev` Cloudflare environment (`CLOUDFLARE_ENV=dev`) so it resolves the same `wrangler.jsonc` block as `dev.plantifiles.com`: one `VARS_ENV=dev` profile and one `plantifiles-dev` D1 binding, local or remote. The local database commands follow the same binding, so no environment fact is stated twice.
- 2026-08-22 — Drop `vars run` from `apps/web`'s `dev` script and carry only `VARS_KEY` in `apps/web/.dev.vars`, mirroring the single `wrangler secret put VARS_KEY` that hosted environments use. SSR executes inside workerd under `@cloudflare/vite-plugin`, whose environment comes from `wrangler.jsonc` plus `.dev.vars`; the wrapper only decrypted into the vite process, so it cost an interactive PIN prompt per start and still left `VARS_KEY` unset for the Worker. `CLOUDFLARE_INCLUDE_PROCESS_ENV=true`, the documented Cloudflare opt-in for forwarding process env, does not work under the vite plugin — measured.
- 2026-08-22 — Delete the `LOCAL_DEV` cookie identity, the dev-only shell, and the seeded demo user. Clerk is the identity provider in every environment, so local development exercises the same session, Organization activation, and request-path projection as production instead of a branch that only ever ran on a developer's machine. The flag also made `dev.plantifiles.com` accept `pf_dev_user` as identity, which was cookie-only impersonation on a public hostname.
- 2026-08-22 — Authenticate end-to-end tests with Clerk's own testing utilities against the development instance: global setup decrypts the vars bundle for credentials, provisions a `+clerk_test` reviewer and an Organization through the Backend API, and `clerk.signIn` mints a sign-in ticket. A test-only authentication bypass would have re-created the branch the previous decision removed.
- 2026-08-22 — Discover the E2E workspace slug at setup time rather than fixing it. The Clerk instance has Organization slugs disabled, so it rejects a requested slug and appends a numeric suffix to the name; the workspace URL is whatever Clerk generated.
- 2026-08-22 — Sign the test session in on the not-found page. `clerk.signIn` needs a loaded Clerk client on a page that will not navigate away, and every real route either redirects a signed-out visitor to Clerk or answers 307.
- 2026-08-22 — Run the plan column at the shell width instead of capping it at `--container-measure`. A centered 68ch article inside an 896px shell put the document's left edge 73px inside the wordmark, so the page read as inset chrome; the dashboard and settings already spanned the shell. The reading measure survives for short standalone copy — the error and not-found screens — where there is no other structure to align to.
- 2026-08-22 — Draw plan and decision status as coloured ink plus an icon rather than a tinted pill. Beside the version `Select` — a real control with the same height, radius, and fill — a pill read as a second button, and status is a state the reader observes. The same icon map feeds the dashboard's status filter, so one vocabulary covers the chip and the menu.
- 2026-08-22 — Reserve the scrollbar gutter on `html`. Route length decided whether a scrollbar existed, so navigating from a short dashboard to a long plan moved the centred shell sideways; the gutter makes page geometry independent of content height.
- 2026-08-22 — Delete the E2E reviewer and Organization in a Playwright `globalTeardown`, and refuse to run unless the target origin is localhost. The fixture writes to the Clerk development instance that also backs the public hosted dev Worker, and a `+clerk_test` address accepts the universal development verification code, so a reviewer left behind is a standing Organization admin that anyone reading the fixture could sign in as.
- 2026-08-22 — Give the CLI subprocess an explicit environment in the E2E spec rather than spreading `process.env`. Clerk's testing helpers require the decrypted secret key on the test process, and the CLI has no use for it.
